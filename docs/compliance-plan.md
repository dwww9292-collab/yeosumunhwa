## 0. 한 줄 요약

기능 구현은 상당 부분 진행됐지만, **지침 기준으로는 오픈 불가 상태**다.
특히 아래 두 가지는 기능 추가가 아니라 **구조 결정**이라 가장 먼저 정해야 한다.

1. **클라우드 리전 / CSAP 문제** — 현재 Supabase + Vercel 조합은 국외 리전일 가능성이 높다.
   공공기관 개인정보의 국외 이전 문제이자, 통상 요구되는 CSAP(클라우드 보안인증)
   미충족 사안이다. 이게 확정되지 않으면 아래 보안 작업 상당수가 재작업된다.
2. **개인정보 수집 동의 절차 부재** — 대관신청·회원가입 양쪽 모두 동의 UI가 없다.
   개인정보 보호법 제15조 위반 소지로, 지침 이전에 법 위반 사안이다.

## 2. 구조적 이슈 — 기능 추가로 해결되지 않는 것

### ① 클라우드 리전과 CSAP (최우선 확인)

지방자치단체 출연기관은 통상 **CSAP 인증을 받은 국내 클라우드** 사용을 요구받는다.
Supabase와 Vercel은 해외 사업자이며, 프로젝트 리전이 국외라면 개인정보 보호법상
**국외 이전에 대한 별도 고지·동의**가 필요하고, 시 지침에 따라 아예 불가할 수도 있다.

이 결정에 따라 선택지가 갈린다.

| 시나리오 | 대응 | 영향 |
|---|---|---|
| A. 현행 유지 승인 | Supabase 리전을 서울(`ap-northeast-2`)로 이전 + 국외이전 고지 정비 | 재작업 적음 |
| B. 국내 CSAP 클라우드 요구 | NHN Cloud / 네이버클라우드 등으로 이전. **DB·인증·스토리지 전면 재구축** | 대규모 |
| C. 시청 인프라 입주 | 여수시 정보통신과 제공 환경에 배포 | 아키텍처 재설계 |

> **다른 모든 보안 작업보다 이 확인이 먼저다.** B/C로 결정되면 아래 P1 작업 상당수가 폐기된다.

### ② 정적 호스팅 구조의 한계

현재는 Vite SPA + Supabase 직접 호출 구조다. 서버 계층이 없어서 다음이 **원천적으로 불가능**하다.

- 관리자 IP 접근 제한 (클라이언트 검사는 브라우저 개발자도구로 우회)
- 접속 로그의 신뢰 가능한 서버측 기록
- WAF 연동 지점
- 개인정보 패턴 차단의 서버측 강제

→ 최소한 **API 게이트웨이 계층**(Supabase Edge Functions 또는 서버리스 API)이 필요하다.

### ③ 접속기록 보관 요건

지침은 개인정보처리시스템 접속기록을 **최소 1년(5만 명 이상 2년)** 보관하라고 요구한다.
Supabase 기본 로그로는 불가능하므로, **별도 `access_logs` 테이블 + 트리거/RPC 기록**을
직접 구현해야 한다. 기록 항목: 계정 식별자, 접속 IP, 일시, 수행 업무, 대상 정보주체.

## 4. 웹 접근성 보완 상세 (P1-6)

WA 인증은 항목이 많아 별도로 정리한다. 현재 확인된 것만:

| 항목 | 현재 | 조치 |
|---|---|---|
| 대체 텍스트 | `alt` 없는 `<img>` 21개 | 전수 부여. 장식용은 `alt=""` + `aria-hidden` |
| 아이콘 버튼 | Remix Icon `<i>` 단독 버튼 다수, `aria-label` 2곳뿐 | 모든 아이콘 버튼에 `aria-label` |
| 건너뛰기 링크 | 없음 | 헤더 최상단 "본문 바로가기" 추가 |
| 키보드 접근 | 미검증 | 슬라이더·모달·탭 포커스 트랩 및 ESC 처리 |
| 명도 대비 | 미검증 | 4.5:1 기준 점검. `text-gray-400` 계열 다수 사용 중 |
| 반응형 확대 | 미검증 | 200% 확대 시 콘텐츠 손실 여부 |
| 표 제목/요약 | 미검증 | 조직소개·대관현황 표에 `caption`/`scope` |

> **SPA 구조 주의:** 라우트 이동 시 포커스가 이동하지 않고 스크린리더가 변화를 알리지
> 못한다. WA 심사에서 지적되는 항목이므로, 라우트 변경 시 `<h1>` 포커스 이동 +
> `aria-live` 안내를 함께 구현해야 한다. 앞서 논의한 프리렌더 도입과 함께 처리하면 효율적이다.

## 5. RFP / 과업지시서 반영 문구 (초안)

외부 발주 시 아래를 명시해야 업체가 준수한다.

```
1. 웹 접근성
   - 「지능정보화 기본법」에 따른 한국웹접근성품질인증(WA) 획득을 과업 범위에 포함하며,
     인증 획득 시점까지 무상 보완한다.
2. 개발 보안
   - 행정안전부 「소프트웨어 개발보안 가이드」의 47개 보안약점을 제거하고,
     진단도구 점검 결과 보고서를 검수 산출물로 제출한다.
   - 국가정보원 「국가 정보보안 기본지침」 및 OWASP Top 10 기준 웹 취약점 점검을
     오픈 전 완료하고 조치결과 보고서를 제출한다.
3. 관리자 보안
   - 관리자 URL 은닉, 허용 IP 접근제한, 2차 인증(OTP/SMS), 세션 타임아웃을 구현한다.
4. 개인정보
   - 개인정보처리시스템 접속기록을 최소 1년(정보주체 5만 명 이상 시 2년) 보관한다.
   - 개인정보 저장 시 비밀번호는 단방향, 그 외 개인정보는 AES-256 이상 양방향 암호화한다.
   - 게시물 등록 시 개인정보 패턴 자동 검출·차단 기능을 탑재한다.
5. 인프라
   - 개인정보를 처리하는 시스템은 국내 리전에 구축하며,
     클라우드 이용 시 CSAP(클라우드 서비스 보안인증) 획득 서비스를 사용한다.
6. 산출물
   - 시큐어코딩 진단보고서, 웹취약점 점검·조치보고서, WA 인증서,
     개인정보 영향평가 대상 여부 검토서
```

## 부록: 현재 잘 되어 있는 것

지적만 나열하면 오해가 생기므로 함께 기록한다.

- 주민등록번호 등 고유식별정보를 수집하지 않는다 (설계 단계에서 회피됨)
